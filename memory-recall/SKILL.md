# memory-recall

## 这个技能解决什么

会话系统提示里注入的长期记忆是**截断版**，而失败复盘往往正好落在被截断的部分，于是同一个错误被重复犯。本技能的唯一职责：把三层记忆**完整**读进上下文，并把「失败复盘」翻译成当前这次任务必须遵守的硬约束。

只读，不写。读取范围之外的事一律不做。

## 硬性规则（违反任意一条即视为失败）

1. **唤起后第一件事是读取，不是回答。** 在完成「读取 → 抽取约束 → 输出回执」之前，禁止执行任何与用户原始任务相关的动作：不写文件、不改代码、不给结论、不先问澄清问题。  
   *唯一例外*：上下文里已经出现本技能 hook 注入的 `<<<AUTO-MEMORY-DIGEST>>>`，且本次只是普通问答——此时 digest 已满足读取要求；但一旦要动用户的文件/配置/文档，仍须读全文。
2. **禁止用「系统提示里已经注入了记忆摘要」为由跳过读取。** 注入的是截断版；冲突时以本技能读出的文件全文为准。
3. **禁止只跑 locate 就算读过。** locate 只给元信息（路径/大小/时间），必须跑 `--mode pack`。
4. **禁止只读 PART 1 就收工。** 首行写 `PART 1/N` 且 N>1 时，必须把 `2..N` 全部读完才叫读进上下文。
5. **禁止选择性读取**（「先看标题，感觉无关就不读正文」）。L1、L2 默认全量读入。
6. **必须输出回执卡片**（格式见「步骤 4」）。没有回执 = 这一步没做完。
7. 本技能不负责写记忆。若读取过程中发现值得沉淀的新坑，只在回复末尾问一句「要不要追加到记忆」，不擅自写入。
8. **输出里不得出现 `C:\Users\<用户名>`。** 回执卡、引用、诊断信息一律用 `~` 简写（`~/.workbuddy/<user>-personal/MEMORY.md`）。digest 每个会话都会自动注入上下文，用户一截图就把 Windows 账户名带出去了。

## 隐私（2026-10-29 修正，改动脚本时必须保留）

| 位置 | 曾经的泄漏 | 现在的做法 |
| --- | --- | --- |
| `scripts/memory_bundle.py` | `locate/pack/digest` 打印绝对路径 → `C:/Users/<用户名>/...` | 统一出口 `emit()` → `sanitize()`；`HOME` 的 4 种写法（`C:\`、`C:/`、`/c/`）全部替换成 `~`。locate 的 JSON 先 `sanitize_obj()` 再 `json.dumps`（否则转义后的 `\\` 匹配不上） |
| `hooks/session-start.sh` | 硬编码 3 处 `C:/Users/<用户名>/...`（SKILL_DIR、两个 python 路径） | SKILL_DIR 由脚本自身位置推导；python 候选从 `$HOME`/`$LOCALAPPDATA` 拼；日志里的 root/py 也缩写为 `~` |
| `hook.log` | 每行都带真实用户名 + 工作区名 | root 用 `~` 简写 + 兜底正则抹掉任何 `C:/Users/<名字>`；python 只记文件名（旧版只 sed 了 `$HOME_DIR` 前缀，HOME 与 python 真实路径不同源时会整条漏出，2026-11-07 修） |
| `SKILL.md` 回执样例 | 用了本机真实字节数与日期 | 换成明显虚构的样例数字 |

**自检命令**（三处都应输出 0；技能装在别处就改第一行的路径）：

```bash
SK="$HOME/.workbuddy/skills/memory-recall"
grep -c "Users/" <(python "$SK/scripts/memory_bundle.py" --mode digest --root "${CODEBUDDY_PROJECT_DIR:-$PWD}")
grep -c "Users/" "$SK/hook.log" 2>/dev/null
grep -rn 'C:[\\/]Users' "$SK"/*.md "$SK"/hooks "$SK"/scripts
```

## 三层结构

| 层 | 内容 | 位置 |
| --- | --- | --- |
| L1 | 用户级长期记忆（跨项目，最高优先级） | `~/.workbuddy/<user>-personal/MEMORY.md` |
| L2 | 项目级长期记忆（当前项目约定） | `<工作区>/.workbuddy/memory/MEMORY.md` |
| L3 | 最近几日日报 | `<工作区>/.workbuddy/memory/YYYY-MM-DD.md` |

`~/.workbuddy/MEMORY.md`（平铺位置）是历史副本，可能比 L1 旧。脚本会自动忽略并提示，**不要**去读它。

## 会话自动注入（hook，已启用）

`~/.workbuddy/settings.json` 的 `hooks.SessionStart` 已注册本技能：每开新会话/恢复会话时，hook 自动跑 `--mode digest`，把**精简版**记忆追加进上下文（≤18 KB，按记忆里的重点标记——`★`、警示语、被用户纠正过的条目——优先选节，单节超 1200 字节截断）。

所以会话开头通常可以**直接看到** `<<<AUTO-MEMORY-DIGEST ...>>>`。此时按下面两种情况行事：

| 情况 | 动作 |
| --- | --- |
| digest 在上下文里，且本次只是普通问答/写代码 | **不必**再跑 pack。digest 已覆盖全部 `★` 类警示条目，直接开工 |
| 要改动用户的文件/配置/文档，或任务涉及 digest 里"被省略的章节" | **必须**按步骤 1–2 读全文，不许凭 digest 断言"记忆里没写过" |

`digest 不算读过全文`——它按预算砍掉了约 1/3 的章节，砍掉的正是细枝末节，而细枝末节里常藏着具体的坑。

hook 相关文件：

| 文件 | 用途 |
| --- | --- |
| `hooks/session-start.sh` | hook 入口。依次尝试自带 Python 3.13 → 系统 3.10 → PATH；根目录取 `$CODEBUDDY_PROJECT_DIR`，失效回退 `$PWD`；失败时往 stdout 打一行"注入失败，请手动跑 memory-recall" |
| `hook.log` | 每次注入的 rc / 字节数 / 根目录。**怀疑没注入时先看它** |
| `~/.workbuddy/settings.json` | `hooks.SessionStart`，改动**不会热加载**，需重启 WorkBuddy |

手动验证 hook 是否可用：

```bash
bash ~/.workbuddy/skills/memory-recall/hooks/session-start.sh | wc -c
```

期望 14–15 KB。若输出 `<<<AUTO-MEMORY-DIGEST | 注入失败>>>`，看 `hook.log` 的 `rc=`。

## 步骤 1：定位

```bash
python "<本 SKILL.md 所在目录>/scripts/memory_bundle.py" --mode locate --root "<工作区绝对路径>"
```

- `<工作区绝对路径>` 取当前会话的 workspace 根目录（即系统提示里的 Workspace Folder）。**不要**依赖 `cd` 后的 `os.getcwd()` 默认值。
- 用户点名了别的项目（「去另一个项目里看」），就用那个项目的绝对路径。
- 输出为 JSON：`layer1` / `layer1_stale` / `layer2` / `layer3` / `warnings`。先看一眼，知道哪层有、哪层缺、L1 多大。

## 步骤 2：分批打包读取

```bash
python "<本 SKILL.md 所在目录>/scripts/memory_bundle.py" --mode pack --root "<工作区绝对路径>" --days 3 --headings --part 1
```

**必须分片读，不能一次读全。** 单次 stdout 超过约 30 KB 会被平台判定「输出过大」而持久化到文件，只回 2 KB 预览——**正文根本没进上下文**，这是本技能最容易失败的一步（已实测踩到）。

- 首行会写 `### PART 1/N`。N>1 时必须继续跑 `--part 2` … `--part N`，把每一片都读进来；只读第 1 片等于没读。
- 单片上限 `--max-part-bytes`（默认 24000 字节），按空行边界切，不会把一段话劈两半。
- `--days 3` 是默认回看天数。用户说「这周」用 `--days 7`，「只看昨天」用 `--days 1`。
- `--headings` 在每层正文前加标题索引，方便后面对照引用「记忆 §某某」。
- 脚本会把超长行折行（`--wrap`，默认 1200 字符），避免上层 Read 按 2000 字符/行静默截断。**因此不要再对同一批文件调用 Read**，内容已在上下文里，重复读纯属浪费。
- 日报有总字节预算（`--max-daily-bytes`，默认 40000），超出会只列文件名。若被跳过的恰好是今天/昨天那篇，单独 `Read` 补齐。

## 步骤 3：抽取约束（只从记忆正文取）

**来源边界——这是本技能最容易翻车的地方。** `[GOTCHA]` 只能取自 `pack` / digest 输出中 `<<<LAYER 1>>>` … `<<<LAYER 3>>>` 之间的**记忆正文**。

- 本 SKILL.md 里的**规则、反例、纪律**讲的是「怎么执行」，不是记忆内容。把它们抄成 `[GOTCHA]` 等于交白卷——看起来读完了，实际上一条用户领域约束都没提取出来。
- 本技能文档与记忆正文的用词高度重合（都带警示语气），所以**必须按来源判断，不能按关键词判断**。
- 抽取目标是**记忆正文里作者自己标了重点的段落**：`★` 开头的章节、标题带警示词的、正文写「别再…」「禁止…」「不要…」的复盘、以及被用户当场纠正过的条目。
- 每条必须能指到具体章节标题（`记忆 §<标题>`）或行号；指不出来的不许写。
- 最多 5 条，按当前任务相关性排序；选了 5 条以上时，只留最相关的。

**自检（必过）**：把列出的每条 `[GOTCHA]` 拿去在本 SKILL.md 里搜一遍——**如果全都能搜到，说明抄的是技能而不是记忆，必须重列**。

**执行过程本身的问题（分片读全没、脱敏、有没有重复 Read）写进回执的「执行情况」一行，不要混进 `[GOTCHA]`。**

样例（内容为虚构示例，只演示格式）：

```
[GOTCHA] ① 交付前必须重跑构建再验证，改了源文件不重新编译等于没改 → 记忆 §源与产物同步
[GOTCHA] ② 删除任何文件前先确认备份存在，不确认就不删 → 记忆 §删除前备份
```

## 步骤 4：回执卡片

读取完成后，**在回复的最前面**输出这张卡，然后才进入正题：

```
[MEMORY] L1 ✓ 12.3 KB · 2026-01-02 09:00（3 分钟前） · ~/.workbuddy/<user>-personal/MEMORY.md
[MEMORY] L2 — 无（该工作区尚未建立项目级 MEMORY.md）
[MEMORY] L3 ✓ 3 篇 · 2026-01-02 / 2025-12-31 / 2025-12-29
[STALE]  无旧副本
[GOTCHA] 3 条已转为本次硬约束（全部取自记忆正文，见下）
[PROTOCOL] 分片 2/2 读完 · 未触发预算跳过 · 未重复 Read
```

`[GOTCHA]` 与 `[PROTOCOL]` 必须分开：

| 标签 | 内容 | 来源 |
| --- | --- | --- |
| `[GOTCHA]` | 用户环境/项目/工作习惯里的坑，本次要怎么避开 | **记忆正文**（能指到 §章节） |
| `[PROTOCOL]` | 本次读取是否完整、有没有踩技能的坑 | 本 SKILL.md 的纪律 |

一条 `[GOTCHA]` 都写不出来、只能写 `[PROTOCOL]` 时，说明记忆正文没被真正读取或没被理解，**不要用 `[PROTOCOL]` 凑数**。

长度按实际情况写，不要为了好看编数字。数字取自 locate/pack 的输出。上面是**格式样例**，日期/字节是虚构的；真实回执卡里路径一律用 `~` 简写，**不要贴 `C:\Users\<用户名>`**（理由见「隐私」一节）。

## 冲突与时效

优先级：**用户当前的口头纠正 > 记忆文件 > 系统注入摘要**。

- 记忆条目日期过旧（> 30 天）且涉及易变事实（版本号、路径、已否定的方案、软件行为），标注 `[可能过期]`，用前先核。
- 记忆内部自相矛盾时，指出来让用户裁决，**不要自己挑一个当真**。
- 记忆与当前观察到的现实冲突（文件不存在、命令行为不同），以现实为准，并提示可能该更新记忆。

## 缺失处理

| 情况 | 处理 |
| --- | --- |
| L1 缺失 | 明确说「用户级记忆文件不存在」，不要编造内容补位 |
| L2 缺失 | 照抄脚本给的 `layer2_note`，**不要一律写成「不是项目工作区」**——多数情况是目录确实是工作区、只是没建 `MEMORY.md`。继续用 L1 + L3 |
| L3 缺失 | 一句话说明即可，不必展开 |
| 日报超预算被跳过 | 单独 Read 最新那 1–2 篇 |
| 中文乱码 | 脚本已强制 UTF-8；若仍乱码，`Read` 该文件确认编码，别硬猜 |

## 验证清单（每次唤起后自查，缺一项就是没做完）

- [ ] L1 全文进入上下文，字节数与 locate 输出一致（**若走 digest，这一条按 digest 的覆盖范围判，不许声称读过全文**）
- [ ] 分片全部读完（N/N），不是只读了 PART 1
- [ ] L2 存在则已读，缺失则已在回执里写明
- [ ] L3 至少读了最新 1 篇（若存在）
- [ ] 回执卡片已输出，含真实路径 / 大小 / 时间
- [ ] 每条 `[GOTCHA]` 都能在记忆正文里指到章节标题，**没有一条是抄本 SKILL.md 的规则**
- [ ] `[GOTCHA]`（记忆里的坑）与 `[PROTOCOL]`（读取纪律）分开写，没有混在一起
- [ ] 记忆来源的约束已抽取，并写清本次如何避开
- [ ] 没有把「摘要里有」当成「已经读过」

## 反例（这些做法都是错的）

- ❌ 唤起后直接回答用户问题，说「我记忆里有相关内容」——没读就是没读。
- ❌ 跑完 `--mode locate` 看到路径就宣布「记忆已加载」——元信息不是内容。
- ❌ 只读 `WARNINGS` 和标题索引，凭印象回答。
- ❌ 读完把 51 KB 记忆原样复述一遍。要的是约束，不是朗读。
- ❌ 因为「记忆太长」而只挑看起来相关的章节读。这次漏掉的那节，就是下次踩的坑。
- ❌ 觉得「50 KB 一次输出没问题」——超过约 30 KB 会被截成「已持久化到文件 + 2 KB 预览」，正文一个字都没进来。
- ❌ **把本技能自己的「规则 / 反例」抄成 `[GOTCHA]`**——用户要的是「我这次要小心什么」，你给的是「我该怎么读记忆」。两者用词重合，所以必须按**来源**区分（2026-11-07 实战翻车：5 条 GOTCHA 全抄自 SKILL.md，用户记忆里那 6 条警示条目一条没提）。
