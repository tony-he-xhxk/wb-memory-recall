# three-layer-memory-recall

> **三条铁律（与本文任何段落冲突时，以这三条为准）**
> 1. **交付物优先。** 用户要的文件/结论没落地之前，不做记忆侧的任何事。
> 2. **两个维度分开。** 「读不读记忆」由用户是否要求记忆决定；「写成什么样」由用户这句话的格式要求决定。两者互不影响，可以同时满足。
> 3. **交付文件里只有用户要的正文。** 读取说明、分档理由、流程自述一律不进文件。

本技能的「回应风格」就是：**直接给答案，不写流程说明、不写分档理由、不贴状态块。**

## 什么时候读记忆

| 用户说了什么 | 动作 |
| --- | --- |
| 显式唤起：`/three-layer-memory-recall`、「完整加载记忆」「把踩坑转成这次的硬约束」「把记忆读进来」 | 读，且必须读完（分片 N/N） |
| 提到过去：「你记得吗」「上次那个坑」「按我的习惯来」 | 读相关层（一般 L1，必要时加 L2/L3），不必全量 |
| 只问了问题、要代码、要结论，没提记忆 | 不读。系统提示里的 digest 够用 |

**显式唤起优先级最高，不会被任何内容类判据降级。** 用户既唤起又要「只要一行代码」时：**照读不误，但只输出代码 + 一句说明**。读完不写出来，和没读是两回事。

反之，用户没提记忆、只问了一个技术问题，就不要自作主张跑全量——那种情况下「读了」是扣分项，不是加分项。

## 交付优先

固定顺序：① 用户的交付物 → ② 对话里的说明 → ③ 记忆维护（写条目、改 `settings.json`、注册 hook、自检）。

1. **用户点名要文件时，「回应正文写进那个文件」本身就是交付物。** 「把完整回应写成 `./output/xxx.md`」「存成 md」都属此类。第一个动作就是 `Write`，内容是用户要的正文，不是骨架、不是计划。目录不存在就先建目录再写。
2. **交付文件里不许出现**：`[MEMORY]`/`[GOTCHA]`/`[PROTOCOL]` 等回执块、逐层状态行、「我判了哪一档」「我先读了什么」这类流程自述、以及技能名/规则名。文件里只有用户要的东西。
3. **维护类动作一律排在交付之后。** 轮次或预算不够时，交付照做，维护动作留成「待办 + 可直接执行的命令」并注明本轮未执行。为跑仪式把交付挤掉，是本技能最严重的失败。
4. **排查类问题最多 2 条诊断命令就下结论**（hook 挂没挂、配置生效没）。查不完就如实写「未能确认，建议这样验证：`<命令>`」，不把整轮耗在排查上。

## 对话里怎么说明读取情况

**默认不用块式卡片**，一句话带过，跟随用户要求的文风：

```
已载入 L1 + L3，其中 3 条与本次相关：<一句话概括>
```

只有用户明确要状态（「读到没有」「哪层有哪层没有」「给我个检查结果」）时，才用块：

```
[MEMORY] L1 ✓ 12.3 KB · 2026-01-02 09:00 · ~/.workbuddy/<user>-personal/MEMORY.md
[MEMORY] L2 — 无（该工作区尚未建立项目级 MEMORY.md）
[MEMORY] L3 ✓ 3 篇 · 2026-01-02 / 2025-12-31 / 2025-12-29
[GOTCHA] 3 条已转为本次硬约束（全部取自记忆正文）
[PROTOCOL] 分片 2/2 读完 · 未重复 Read
```

- 用户说过「别展开」「一句话」「只要代码」「写到文件里别加别的」，或要求仿某种文风时，**上面两种都不给**，直接进正文。
- 只读了 `PART 1/N`（N>1）时，`[PROTOCOL]` 必须如实写「只读了 1/N」，不许写「已读完」。
- 样例里的日期与字节是虚构的，真实回执的路径一律用 `~` 简写，**不贴 `C:\Users\<用户名>`**。

## 读取步骤

### 1. 定位

```bash
python "<本 SKILL.md 所在目录>/scripts/memory_bundle.py" --mode locate --root "<工作区绝对路径>"
```

`<工作区绝对路径>` 取系统提示里的 Workspace Folder，不要依赖 `cd` 后的 `os.getcwd()`。输出 JSON 含 `layer1`/`layer1_stale`/`layer2`/`layer3`/`warnings`，先看哪层有、哪层缺。

### 2. 分片打包

```bash
python "<本 SKILL.md 所在目录>/scripts/memory_bundle.py" --mode pack --root "<工作区绝对路径>" --days 3 --headings --part 1
```

- **必须分片。** 单次 stdout 超约 30 KB 会被平台判「输出过大」持久化到文件、只回 2 KB 预览，正文根本没进上下文——这是本技能最容易失败的一步。
- 首行写 `### PART 1/N`，N>1 就继续 `--part 2` … `--part N`，全读完。只读第 1 片等于没读。
- `--days` 默认 3；用户说「这周」用 7，「只看昨天」用 1。
- 只读相关层时（用户只问及过去某项），可 `--days 1` 或只读 L1。
- 脚本已把超长行折行（`--wrap` 默认 1200），**不要再对同一批文件调用 Read**，内容已在上下文里。
- 日报有总预算（`--max-daily-bytes` 默认 40000），超出只列文件名；被跳过的若是今天/昨天那篇，单独 `Read` 补齐。

### 3. 抽取约束（只从记忆正文取）

`[GOTCHA]` 只能取自 `pack`/digest 输出中 `<<<LAYER n>>>` 之间的**记忆正文**。本 SKILL.md 的规则、反例讲的是「怎么执行」，抄过来等于交白卷——两者用词高度重合，必须按**来源**判断，不能按关键词判断。

- 目标是记忆里作者自己标了重点的段落：`★` 章节、标题带警示词的、写「别再…」「禁止…」的复盘、被用户当场纠正过的条目。
- 每条必须能指到 `记忆 §<标题>` 或行号，指不出来就不写。最多 5 条，按相关性排序。
- **自检**：把列出的每条拿去在本 SKILL.md 里搜一遍，如果全都能搜到，说明抄的是技能而不是记忆，必须重列。
- 读取过程本身的问题（分片读全没、有没有重复 Read）写进 `[PROTOCOL]`，不混进 `[GOTCHA]`。

## 写入、修正与删除

只在用户显式要求时进入本节，且**只动用户点名的那一条**。读取流程本身不改任何文件。

### 三条边界（实测最易越界的地方）

1. **一次口述 = 一条记录。** 用户说一件事就写一条，不许顺手加「由此推出的规则」，也不许把一句话拆成两条。
2. **一次性指令不落盘。** 「这次别留备份」「别展开」「直接改」是本次操作的要求，不是要记的规则。只有用户说「以后都……」「把这条记下来」时才写成长期条目。
3. **旧条目只由用户授权改动。** 发现新条目与已有条目看似冲突，**只在回复里问一句**（「这条和 §XXX 看着冲突，要一起改吗」），不动文件，绝不自己标「已被推翻」。

### 追加

1. **定层**：跨项目通用 → L1；只跟当前项目有关 → L2 `<工作区>/.workbuddy/memory/MEMORY.md`。用户点名了就按用户说的。
2. **追加不覆盖**：在末尾按原有格式加一条，不动已有条目；文件不存在就新建，首行给标题。
3. **格式**：`## <当天真实日期> <一句话标题>`，正文按「现象 / 根因 / 以后怎么做」三段。
   - **用户只讲了现象和以后怎么做时，根因写「（根因未确认）」或整段省略，不许替用户推断。** 缺哪段就缺哪段，三段齐全不是硬要求。
   - 用户已口述清楚的内容照原话落盘，不替他重新发挥。
4. 写完 `Read` 回读确认，回一句「已写入 L1（或 L2）§标题」。

### 删除与修正（仅在用户点名要改时）

1. `Grep` 定位，把待删/待改的**原文**贴给用户（用户已说不用确认就跳过）。
2. 整段删除前复制 `MEMORY.md.bak-YYYYMMDD`；**用户本次说「别留备份」就不复制**，也不再问一次。这是本次操作的要求，不要写成长期规则。
3. 只改局部时按用户原话改，不顺手润色别处，也不顺带处理「看起来过期」的相邻条目。
4. 完成后回一句改了哪条、还剩几条，不复述全文。

## 初始化（安装与自检）

**安装永远让位于交付。** 用户当前有具体任务时先完成任务，安装留作待办，不许用安装动作把交付挤出去。

1. 技能目录放到用户级目录：`cp -r three-layer-memory-recall ~/.workbuddy/skills/`
2. **询问一次，除非用户已授权**：要不要每个会话开头自动注入精简版记忆。用户说「直接挂」「不用问了」「我授权」→ 跳过询问直接进第 3 步，重复询问算未完成。用户否定 → 不注册 hook、不提重启，到此结束。
3. 用户肯定时注册钩子，编辑 `~/.workbuddy/settings.json` 顶层加 `hooks`（已有就合并）：

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command",
        "command": "bash \"$HOME/.workbuddy/skills/three-layer-memory-recall/hooks/session-start.sh\"",
        "timeout": 30 } ] }
    ]
  }
}
```

4. **重启 WorkBuddy 必须由用户亲自完成**，配置不热加载。
5. 重启后请用户点「新建任务」开新对话，原样发送：

> 能看到一个精简的记忆列出了踩坑等吗？之前我加了hook，这次是测试运行，看看这个hook有没有被挂上。

判据：出现 `<<<AUTO-MEMORY-DIGEST | 由 SessionStart hook 自动注入>>>` 且带正文节选 = 挂上了；出现「注入失败」= 没挂上，看 `hook.log` 的 `rc=`；什么都没有 = 回第 3 步核对 `settings.json`。

不重启也能验脚本本身：`bash "$HOME/.workbuddy/skills/three-layer-memory-recall/hooks/session-start.sh" | wc -c`。判据不是绝对字节数，看三条：≠0 且不含「注入失败」= 正常（约为记忆总量的 70–90%，上限 18 KB）；=0 = 这台机器还没有记忆文件（正常）；出现「注入失败」= 看 `hook.log`。

依赖只有 `python3`（或 `python`），脚本只用标准库；Windows 上钩子由 Git Bash 执行。

## 已注册 hook 时的会话开头

上下文里出现 `<<<AUTO-MEMORY-DIGEST>>>` 时：

| 情况 | 动作 |
| --- | --- |
| 普通问答、写代码 | 不必再 pack，digest 已覆盖 `★` 类警示条目 |
| 要改用户的文件/配置/文档，或涉及被省略的章节 | 必须按读取步骤读全文 |

**digest 不算读过全文**——它按预算砍掉约 1/3 章节，砍掉的细枝末节里常藏着具体的坑。

## 三层结构与降级

| 层 | 内容 | 位置 |
| --- | --- | --- |
| L1 | 用户级长期记忆（跨项目，最高优先级） | `~/.workbuddy/<user>-personal/MEMORY.md` |
| L2 | 项目级长期记忆 | `<工作区>/.workbuddy/memory/MEMORY.md` |
| L3 | 最近几日日报 | `<工作区>/.workbuddy/memory/YYYY-MM-DD.md` |

`~/.workbuddy/MEMORY.md`（平铺位置）是历史副本，可能更旧，脚本会忽略并提示，**不要读它**。

| 现象 | 怎么做 |
| --- | --- |
| 三层全缺，pack 只回 1 KB 占位 | 明说「还没有记忆文件」，跳过提取，直接用系统提示与当前上下文完成任务。不许编一张看起来很饱满的假回执 |
| 只有 L1，L2/L3 缺 | 用 L1 的约束继续，回执照实写缺失，不追问、不停下 |
| 读到内容但抽不出 `[GOTCHA]` | 回执写「0 条约束（记忆未含同类复盘）」，正常交付。不拿本文档规则凑数，也不停工 |
| 脚本报错 / 没有 python | 手工 `Read` L1、L2、最新日报，注明「脚本不可用，已手工读取」 |
| 目标项目没有 `.workbuddy` | 一句告知，按无记忆继续，不追问要不要新建 |

**任何降级都不阻塞交付。** 记忆是加速器，不是通行证。

冲突时优先级：**用户当前的口头纠正 > 记忆文件 > 系统注入摘要**。条目日期超 30 天且涉及易变事实（版本、路径、已否定的方案）标 `[可能过期]`；记忆自相矛盾时指出来让用户裁决，不自己挑一个当真；与现实冲突以现实为准。

## 隐私

脚本已统一脱敏：`emit()` 出口把 `HOME` 的四种写法（`C:\`、`C:/`、`/c/`）换成 `~`，`hook.log` 里 root 用 `~`、python 只记文件名。自检（三处都应输出 0）：

```bash
SK="$HOME/.workbuddy/skills/three-layer-memory-recall"
grep -c "Users/" <(python "$SK/scripts/memory_bundle.py" --mode digest --root "${CODEBUDDY_PROJECT_DIR:-$PWD}")
grep -c "Users/" "$SK/hook.log" 2>/dev/null
grep -rn 'C:[\\/]Users' "$SK"/*.md "$SK"/hooks "$SK"/scripts
```

## 自检（按顺序，前三条不过就不用看后面的）

- [ ] 用户要的东西已落地：点了名要文件，那个文件里就是完整正文
- [ ] 交付文件里没有回执块、没有分档理由、没有流程自述
- [ ] 用户要求读时读了，读完的层数如实（只读 1/N 就没写「已读完」）
- [ ] 每条 `[GOTCHA]` 都能指到 `记忆 §章节`，没有一条抄自本 SKILL.md
- [ ] 用户说过不用确认/不用备份/别展开时，对应动作一项都没出现
- [ ] 记忆为空时走了降级路径，说清缺什么、任务照常交付

## 反例

- ❌ 用户显式唤起又要「两行代码 + 一句说明」，因为「拿不准取低档」就把唤起降级，代码给了、记忆没读。
- ❌ 把分档理由、「我先读了哪几层」写进交付文件开头，文件里一半是流程自述。
- ❌ 用户要的 `output/` 目录建好了，文件始终是空的，整轮耗在改 `settings.json` 和注册 hook 上。
- ❌ 用户说「别留备份文件，嫌乱」，还是生成了 `settings.json.bak`。
- ❌ 用户只讲了现象和以后怎么做，却补写了一条自己推断的根因写进 L2。
- ❌ 用户只问一句 pandas 怎么写，却手工探查三层目录、翻 `hook.log`、建 `.workbuddy/memory`。
- ❌ 跑完 `--mode locate` 看到路径就宣布「记忆已加载」——元信息不是内容。
- ❌ 只读 `WARNINGS` 和标题索引就凭印象回答；或因「记忆太长」只挑看起来相关的章节读——漏掉的那节就是下次踩的坑。
- ❌ 把 51 KB 记忆原样复述一遍。要的是约束，不是朗读。
- ❌ **把本技能自己的规则/反例抄成 `[GOTCHA]`**——用户要的是「这次要小心什么」，你给的是「我该怎么读记忆」。
- ❌ 用户已经说过「直接挂」「我授权」，还回一句「按规矩我得先问你一次」。
- ❌ 用户说「记下来」回「本技能只读」，说「删掉那条」回「读取范围之外不做」。
- ❌ 用户口述一个 bug 要求记住，却顺手把 L1 里相邻的「改配置前先备份」标成「已被推翻」并改写——一次性指令不是长期规则，旧条目也不是你能自己宣布作废的。
